Das Konzept

Eine Disziplin.
Zwei Ergebnisse.

Wir schreiben Tests mit klar benannten test.step()-Blöcken. Jeder Aktions-Schritt wird sofort von einem Ergebnis-Schritt gefolgt.

Diese Namen dienen zwei Zwecken gleichzeitig:

  • Playwright Trace — lesbar im Report und im Debugger
  • TestRail Testfall — automatisch exportierbar

Aktion → Ergebnis

Im Code & in TestRail

TypeScript

await test.step(
  'Der Benutzer klickt auf "Login".',
  async () => {
    await page
      .getByRole('button', { name: 'Login' })
      .click();
  });

await test.step(
  'Die Produktseite wird angezeigt.',
  async () => {
    await expect(page)
      .toHaveURL(/inventory/);
  });

TestRail Integration

3 Befehle. 1 Ergebnis.

# 1. Eigenen Abschnitt anlegen
npx tsx scripts/testrail/add-section.ts \
  "Anna_Zhadova"
→ ✅ Section created: id=58988
→ TR_SECTION_ID=58988 in .env setzen

# 2. Testfall-Datei generieren
npx tsx scripts/testrail/generate-cases.ts \
  tests/01-anmeldung/assignment.spec.ts \
  --out scripts/testrail/cases/Anna/login.ts

# 3. Nach TestRail übertragen
npx tsx scripts/testrail/create-case.ts \
  scripts/testrail/cases/Anna/login.ts
→ ✅ Created C1234 — Anmeldung mit gueltigen Zugangsdaten

Best Practices

Tipps

  • Erst Codegen, dann aufräumen — Happy Path aufzeichnen, CSS-Selektoren durch getByRole() ersetzen
  • Trace Viewer — bei Fehlern sofort den Trace öffnen, nicht raten
  • Paaring ist Pflicht — Aktion gefolgt von Ergebnis, sonst bricht der TestRail-Export
  • test.only — während der Entwicklung nur einen Test ausführen
  • Cursor Auto-Modus vermeiden — explizit Claude oder GPT-4o wählen
  • Claude Code Plan Mode — für komplexe Tests zuerst planen, dann generieren
  • Locator-Priorität — getByRole → getByLabel → getByTestId → CSS nur als letztes Mittel
  • Page Objects optional — mit AI-generierten Tests oft nicht nötig
